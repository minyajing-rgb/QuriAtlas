# Definition before implementation
Read the current repo/app and latest owner decisions. READ full PRD, flows and architecture; render and INSPECT actual desktop/mobile mockups. Filenames, summaries and code are not visual evidence. Preserve approved design and product identity.
Produce versioned PRD, full concrete page/feature/state/branch matrix and IDs, per-screen UI/reference/approval, all success/error/empty/loading/permission/cancel/back/refresh flows, component/data/API/auth/privacy/release architecture, self-contained builder request and requirement→screen→flow→test traceability. Cover every dynamic instance and complete language/responsive behavior; do not silently reduce to a homepage.
Deliver and read back this pack in the actual implementation workspace. Respect tool prompt contracts and one writer per app. Obtain actual builder result; send is not completion. Reuse existing recovery, no more backup projects instead of implementation. No unauthorized production/domain/billing/auth/data changes. No fabricated visuals, features, results, model calls or success/metrics.
Automatically perform product-acceptance after building; independently fix/retest before owner review. Missing requirements/reference/evidence are BLOCKED; backend-only NA needs reason.
